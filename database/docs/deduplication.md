# Дедупликация контента и участников

## Принцип

Совпадение регистра, пунктуации или одного имени не является достаточным
основанием для автоматического объединения. `Snoop Dog`, `snoop dog` и близкие
варианты образуют кандидата, после чего система проверяет дополнительные
сигналы.

## Конвейер

1. Приложение выполняет Unicode NFKC, case folding, нормализацию пробелов и
   пунктуации, затем сохраняет `normalizedTitle`/`normalizedName`.
2. `pg_trgm` формирует кандидатов по похожим названиям и псевдонимам.
3. Для кандидатов сравниваются внешние ID, каталоги работ, участники,
   длительность, описания, изображения и fingerprints файлов.
4. Каждый сигнал сохраняется в `content.tDuplicateEvidence`.
5. Итог и версия модели сохраняются в `content.tDuplicateCandidate`.
6. Пороговые значения и веса берутся из `content.tDuplicatePolicy` и
   `content.tDuplicateSignalRule`, а не зашиваются в код.
7. Высокая уверенность с авторитетным сигналом может блокировать повторное
   создание автоматически. Средняя уверенность отправляется сообществу.
8. Объединение создаёт `content.tResourceMerge`; исходный UUID остаётся
   известным и перенаправляется на канонический ресурс.

## Авторитетные сигналы

- один внешний ID у доверенного источника;
- совпадающий аудиофингерпринт;
- совпадающий видеофингерпринт;
- идентичный SHA-256 исходного файла.

Имя, изображение, описание или одинаковая длительность по отдельности не
считаются авторитетными: они только увеличивают confidence.

## Управление без административного предварительного контроля

Автоматическая проверка выполняется до создания публичного дубля. Неочевидный
случай получает workflow `MERGE_DUPLICATE` и может решаться участниками с
соответствующим permission. Жалоба пользователя создаёт отдельный moderation
процесс. Административная роль не является обязательным участником обычной
публикации. В будущем необходимо реализовать скрипт который будет выполнять задачи
по поиску дубликатов.
